- (#262) `g <letter>` used one pending-focus mechanism (`sessionStorage["docubite.pendingFocus"]="rows"`) for every rail destination, but Admin has no row list to consume it — focus silently dropped to `body`. → Any destination without the primitive's usual consumer needs its own consumer or a named exception in the spec, verified live, not assumed from the table. · check: keyboard probe per destination asserts `activeElement !== body`.
- (#262) The shared `Dialog` returned focus to whatever `document.activeElement` was at open time, including `body` (a browse-mode/AT `?` press) — no fallback, so Esc stranded focus on the document root. → A shared focus-return primitive names its `body` fallback (a landmark) once, centrally; don't leave every caller to discover it. · check: any `*-esc-focus-return` keyboard-probe entry resolving to `"body"`.
- (#262) A new keyboard shortcut routed to an existing page (`/search`) whose `page.tsx` had a pre-existing `redirect()` guard for the "no query" case — the guard was never audited against the shortcut's own arrival shape (empty query, by design), so the round read it as a timing flake before someone read the route file. → Before wiring a shortcut/link to an existing route, read that route's server component for guards/redirects that assume a param the new caller won't always pass. · check: the target route's `page.tsx` has no `redirect(` on the exact param state the new caller sends.
- (#262) A cold `next dev` compiles each route on its first hit (50s+ on this box); a capture round that walks eight fresh routes read six of them as broken navigation on the first pass, purely from the compile stall exceeding the probe's wait. → Warm every route the round visits with a `curl` first, or discard the first pass and trust only the second. · check: a round script with no pre-warm step and per-state waits under ~5s on a server that was just started.
- (#264) `components/intake/inbound-address-line.tsx`'s `<code>` pill wrapped mid-token at 1440 even with room in the column — the spec (§3.2) only stated the `<md` break-all rule, not the desktop nowrap rule; fixed with `max-md:break-all md:whitespace-nowrap`. Same shared `<InboundAddressLine>` is #266's second consumer — check it inherits the fix rather than re-introducing bare `break-all`.
- (#264) `components/shell/how-it-works.tsx`'s dialog footer mentioned "Keyboard shortcuts" as plain text; made it a real button calling `openKeyboardShortcutsDialog()` (exported from `keyboard-shortcuts.tsx`) that closes this dialog first, then opens that one — the pattern any dialog that name-drops another dialog should follow.
- (#264) `components/ui/dialog.tsx` has no CSS transitions/animations at all (portal mounts/unmounts instantly) — `prefers-reduced-motion` audits on this primitive are N/A-pass, not "unverified"; don't leave a `?` on the include checklist for a primitive with zero motion to gate.
- (#268) Exceptions' `[exceptionId]` route is keyed by the exception's own id, not the document id every other queue's origin strip resolves against — `describeOrigin` needed a check→document lookup that no other queue needed. → Before writing a generic origin/back-link resolver, grep every queue's dynamic segment name against its Prisma model's id field; don't assume "queue detail route id" always equals "document id". · check: `grep -rn "\[.*Id\]" app/(app)/workspaces/[workspaceId]` against each route's `page.tsx` param-to-model lookup.
- (#268) `gh issue edit <n> --body-file -` piped from a heredoc with the closing marker quoted (`<<'EOF'`) disables `$()` substitution inside it — a `$(gh issue view ...)` placeholder was written to the tracker literally, clobbering the map issue's real body. → Never pipe a placeholder/command-substitution string as `--body-file -`; write the resolved content to a real file first, read it back, and only then pass that file's path to `--body-file`.
- (#271) A build session added `stageReachedAt` to three `reviewTask.update` call sites in `models/review-tasks.ts`/`models/approval-workflows.ts` but never re-ran `models/review-tasks.test.ts`/`models/approval-workflows.test.ts`, leaving four stale `toHaveBeenCalledWith` literals that only surfaced at the close-phase full suite. → After adding a field to an existing Prisma `update`/`create` call, grep the model's own test file for that call's exact `toHaveBeenCalledWith` and update every match in the same edit. · check: `npx vitest run <model>.test.ts <consumer>.test.ts` immediately after the edit, not deferred to close.
