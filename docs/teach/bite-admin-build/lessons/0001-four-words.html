Four words, two axes

You got lost at Companies because Bite had just changed the language underneath it (ticket #300). This lesson gives you the four words and the one rule they hang on, then checks it stuck.

The one idea

There are two axes, and they never mix:

AxisWordsWhat it decides
Company roleOwner · Reviewer · MemberEverything you can do in that company's books and Admin sections
Organization admina single flag, or “—”Renaming the organization; seeing it in Admin. Nothing else.

Belonging to an organization opens no company.

Access to each company is granted separately, with its own role. The same person can be Owner in Acme Ltd and Member in Acme Holdings. Source: CONTEXT.md §Organization, §Role; the reason is ADR 0002 — Workspace.organizationId is a grouping column, WorkspaceMember is the only access grant.

Why #300 said it this way

  • "Workspace" never appears on screen. A team workspace is a Company; your own one is Personal. The word survives only in code and URLs (/workspaces/[id]/…).
  • Organization admin is not a ladder. In the code only createOrganization ever writes an OrganizationMember, and it always writes "admin". There is no org "member", so the screen must not invent one — it shows the fact or “—”.
  • One admin vocabulary. Organization admin (the org), Owner (a company), Admin (the area at the bottom of the rail). No fourth word; the platform operator role is never shown.
Not yet on screen: #300 decided these words, but the execution ticket that renders them (#301) is still open. The switcher still says "Team workspace" and "New workspace" (components/workspace/switcher.tsx lines 48, 54, 79). When you see that, it is a known gap, not a new bug.

Look at it

On the tunnel URL, open the rail's bottom item → Admin. The left column has two captions: Organization (Dashboard, Companies, Users) and the current company's name (Configuration, Approval Flows, …). Dashboard appears only when you belong to two or more companies (admin/layout.tsx line 34).
