Token usage glossary

The words used across every lesson. Stick to these; the logs use them too.

TermMeaning
TokenThe unit the model reads and writes; roughly ¾ of an English word, or 4 characters of prose. Code and JSON tokenize less efficiently.
ContextEverything sent to the model on one call: system prompt, tool schemas, the conversation so far, tool results. The whole of it is re-sent on every call.
TurnOne model call. In an agent session, one tool call ≈ one turn. The log's assistant events, one per turn, each carry a usage block.
LoadThis workspace's word for the context on the first turn, before any work: harness + system prompt + brief. The run log prints it as load NNK.
Prefix cacheAnthropic's prompt cache. A call whose leading bytes match a recent call reads that prefix from cache instead of paying full input price. Match is byte-exact and from the start.
input_tokensUncached input this turn, billed at the base input rate. Tiny in cached agent sessions (2–4 per turn).
cache_creation_input_tokensInput written to the cache this turn (new tool results, a changed prefix). Billed above base input rate.
cache_read_input_tokensInput served from cache this turn. Billed well below base rate, but billed on every turn.
output_tokensWhat the model wrote: text, tool-call arguments, thinking. The expensive per-token rate, but usually under 1% of an agent session's tokens.
Cache TTLHow long a cached prefix survives without being read: 5 minutes by default, 1 hour when requested. Claude Code sessions here show ephemeral_1h.
Hand-off lineThe autopilot's soft context cap. Crossing it asks the session to write its hand-off and stop, so the next session starts small.
Turns × contextThe cost model. Total tokens sent ≈ Σ over turns of that turn's context. Halve either factor, halve the bill.
Sources: Prompt caching · Context windows. Ask the teacher when a term is unclear.
