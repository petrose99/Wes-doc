# Content/keyword SEO strategy

Ticket: [#130 — Content/keyword SEO strategy](https://github.com/petrose99/docubite/issues/130) (Map #126: Multi-page marketing site redesign + SEO)

Feeds the same downstream IA decision as #127/#131 — this file adds keyword-to-page mapping on top of that IA, and a first blog/resources content plan. It does not modify #127's or #129's findings; it builds on them (read those first if you haven't).

This is a planning/spec document only. No page copy, no blog posts, no code — just which terms to target and where they belong, precise enough for a later ticket to execute from.

## Method and limitations

Grounding on what DocuBite actually is and its current page inventory came from a direct code read: `lib/solutions.ts`, `app/(marketing)/page.tsx`, `app/(marketing)/pricing/page.tsx`, and the homepage section components under `components/marketing/landing/` (`accounting.tsx`, `hero.tsx`, `how-it-works.tsx`, `multi-currency.tsx`, `sheets.tsx`) and `components/marketing/sections/integrations-api.tsx`.

External keyword-landscape research used WebSearch only (no Ahrefs/Semrush account access from this environment), against: vendor marketing/blog pages (Ramp, Tipalti, Stampli, ApprovalMax, Rippling) as a primary-source signal of what they title and target; third-party comparison/alternative content (Volopay, Freehand, CB Insights, Peakflo, Rippling) as a signal of which "alternative"/comparison queries the category already has built content around; and Gartner/Ardent-Partners-cited cost stats picked up secondhand through a Zone & Co article. No direct keyword-volume tool (Ahrefs/Semrush/Google Keyword Planner) was queried — search-result presence, competitor content investment, and third-party "best alternatives" round-ups are used as a proxy for real demand, not exact volume numbers. Treat every volume claim below as directional (categorical: high/medium/low relative to the cluster) rather than a number — a follow-up with real Keyword Planner/Ahrefs access should confirm before ad spend or heavy content investment is committed against any single term.

## Product/positioning grounding

DocuBite is an AI accounts-payable / document-to-ledger product, not a generic OCR tool or a spend-management card platform. Reading `lib/solutions.ts` and the homepage sections, the actual product surface is:

- **Core loop**: bills arrive by email/upload/API → extraction (invoices, receipts, expense receipts, bank statements, handwritten documents, scanned PDFs) → fraud checks (bank-detail-change freeze, split-invoice detection, suspicious resubmission) → 2-/3-way PO matching → amount-thresholded, named-approver approval routing → push to QuickBooks/Xero/ERP or DocuBite's own built-in double-entry ledger → bank-ready payment file (ZA EFT/bulk CSV) + remittance advice, with payment execution deliberately left on the bank's own rails (`finance-ops-teams` solution copy is explicit DocuBite is "pay-ready, not pay-executing").
- **Segments already modeled as solution pages** (`lib/solutions.ts`, group `"ap"`): in-house AP controllers, bookkeepers running client AP (multi-tenant, per-client inbound email, practice API), finance-ops teams (aging cockpit, CFO-facing).
- **Document-type pages** (group `"type"`): invoices, receipts, expense receipts, bank statements.
- **Document-quality pages** (group `"quality"`): handwritten documents, scanned PDFs — positioned explicitly as "reassurance layer," not the lead pitch.
- **Current page inventory** (`app/(marketing)/`): `/` (homepage, single long scroll, 18 sections), `/solutions` (index), `/solutions/[slug]` (11 static slugs above), `/demo`, `/pricing` (placeholder, no real tiers yet — TODO in the file itself).
- **Named integrations**: QuickBooks Online, Xero live; Sage/NetSuite on roadmap; Bigcapital as an alternate built-in ledger option; a webhook-backed REST API (`POST /api/v1/documents`, `bill.pushed`/`match.discrepancy`/`check.failed` events).
- **Competitive self-awareness already in the codebase**: `integrations-api.tsx` names Dext by name in a code comment ("Dext's whole pitch... and DocuBite already has it"); `sheets.tsx` names "Dext/Hubdoc/QBO" as the honest baseline for a demo, not a superiority claim. No competitor names appear in rendered copy — consistent with the `no-vendor-names-in-the-ui` project convention (that convention is about not naming the *AI model provider* in-product; it does not obviously extend to naming category competitors in SEO/marketing comparison content, which is normal and expected for this content type — flagged as an open question below).
- **Geography signal**: the finance-ops-teams solution names South African banks by name (Standard Bank, Absa, Nedbank, FNB) and a ZA EFT export — DocuBite has at least one concrete non-US market already reflected in product copy, which matters for keyword localization (see Open questions).

Everything below is grounded in this actual surface — no keyword target is proposed for a capability DocuBite doesn't have (e.g., no "spend management," "corporate card," or "expense management for employees" cluster, because that's Ramp/Brex/Mercury's category, not DocuBite's).

## Keyword target clusters

### Bottom-funnel (high commercial intent, ready to evaluate/buy)

These belong on pages a prospect reaches after already deciding they want AP automation — they should map to pages with a strong CTA, not blog posts.

1. **Core category terms**: "accounts payable automation software," "AP automation software," "invoice processing automation," "invoice automation software." These are the terms every competitor's own homepage and product pages target directly — Ramp, Tipalti, Stampli, Medius, Concur all have a page whose title or H1 is close to a direct match on one of these (`tipalti.com/ap-automation/`, `stampli.com/ap-automation/`, `concur.com/solutions/ap-automation`). High competition (established, well-funded incumbents with dedicated pages and years of backlinks) but also the highest-relevance, highest-intent traffic DocuBite can target — this is the category DocuBite is actually in. Source: WebSearch results for "accounts payable automation software" surfacing Zoneandco, Stampli, Concur, Medius, Tipalti as the ranking set; Gartner/Ardent Partners cost-per-invoice stat ($8–$30/invoice, up to 70% reduction) cited via the Zone & Co article as the kind of quantified pain point competitors lead with.
2. **Segment-qualified variants matching DocuBite's own existing solution pages**: "AP automation for accounting firms," "AP automation for bookkeepers," "accounts payable automation for finance teams." Confirmed as a real, separately-targeted sub-cluster — ApprovalMax has a dedicated `for-accountants-and-bookkeepers` page, Zenwork has a "AP automation software for accounting firms" listicle, and Dext/BILL/Plooto/Tipalti are named repeatedly in that context. Lower absolute volume than the generic category term but much lower competition and a near-exact match to DocuBite's `bookkeepers-running-client-ap` and `ap-controllers` solution pages, which already exist. Source: WebSearch "AP automation for accounting firms / bookkeepers."
3. **Fraud/compliance-specific bottom-funnel terms**: "invoice fraud detection," "duplicate invoice detection," "3-way match invoice," "PO matching software." Real, actively-targeted terms — Ramp, Docsumo, Klippa, Klearstack, Precoro, Rossum, Doxis all have dedicated blog/feature content on exactly these terms, several updated in 2026. This is a genuine differentiation opportunity: DocuBite's `ap-controllers` solution copy explicitly claims fraud checks "Dext-class tools don't run" (bank-detail-change freeze, split-invoice detection) — a real, defensible, currently-underused angle most competitor content treats generically (duplicate detection) rather than the more specific bank-detail-fraud angle DocuBite ships. Source: WebSearch on invoice fraud/duplicate-detection/3-way-match, eight independent vendor blogs already ranking here.
4. **Comparison / "alternative" terms**: "[Dext/Hubdoc] alternative," "Bill.com alternative," "Tipalti alternative." Confirmed as a heavily-invested content type in this category — Ramp itself runs `/blog/top-tipalti-alternatives` and `/blog/top-bill-alternatives`; Rippling, Peakflo, Wingspan all run the same play against BILL and Tipalti. This is bottom-funnel (someone searching "X alternative" is already using or evaluating a named competitor) but also the most directly competitive content to write, since ranking requires naming a competitor by name on a public page — a real departure from the in-product "no vendor names" convention and needs an explicit decision (see Open questions). DocuBite's closest natural target given its own codebase comments is Dext/Hubdoc, not Bill.com/Tipalti/Ramp — DocuBite doesn't compete on spend cards (Ramp) or enterprise global payments (Tipalti), it competes on "does the extraction actually work on messy documents" which is Dext/Hubdoc's exact territory per `sheets.tsx`'s own comment. Source: WebSearch on "bill.com/tipalti/ramp alternative," surfacing Ramp's, Rippling's, and Peakflo's own alternative-page strategy.

### Middle-funnel (comparing approaches, not yet vendor-specific)

5. **Document-type + automation terms** matching DocuBite's existing `"type"` and `"quality"` solution pages: "invoice data extraction," "receipt OCR software," "bank statement data extraction," "scanned PDF data extraction," "handwritten document OCR." Medium volume individually but directly matches five pages that already exist (`invoices`, `receipts`, `bank-statements`, `scanned-pdfs`, `handwritten-documents`) and currently have generic, non-keyword-targeted page titles per the technical SEO audit's finding that `solutions/[slug]/page.tsx` metadata is templated but not confirmed to contain these exact terms. Source: derived directly from `lib/solutions.ts`, cross-checked against category-generic competitor terminology (OCR/data-extraction framing is standard across Docsumo, Klippa, Rossum — all named above as active content producers on adjacent AP terms).
6. **Ledger/ERP-integration terms**: "QuickBooks invoice automation," "Xero bill automation," "AP automation without an ERP" (for the built-in-ledger option). Directly matches DocuBite's named integrations and its differentiated "no second tool to buy" pitch in `accounting.tsx`. Lower competition than generic category terms since it's a narrower intersection (product × specific ledger), and DocuBite has real, shipped functionality to back the claim (not aspirational).

### Top-funnel (educational, blog/resources-suited)

These are the terms a Resources/blog section (per the IA candidate bucket named in `marketing-site-teardown-ramp-vicai-peers.md`'s IA findings — Vic.ai's and Mercury's nav both carry a Resources dropdown with Guides/Blog) should be built around. None of these belong on a product/solutions page — they're informational searches, not purchase-ready.

7. **"How to" / process-education terms**: "how to automate invoice processing," "how to process invoices," "invoice approval workflow," "accounts payable process automation." Directly confirmed as real, currently-ranking content — Ramp's own blog runs `/blog/accounts-payable/how-to-automate-invoice-processing` ("Automated Invoice Processing: A Step-by-Step Guide") and `/blog/accounts-payable/what-is-ap-automation` ("AP Automation: Definition, How It Works & Key Benefits"). Source: WebSearch surfacing Ramp's own accounts-payable blog vertical directly.
8. **ROI/business-case terms**: "AP automation ROI," "cost of manual invoice processing," "accounts payable automation benefits." Confirmed real — Ramp runs `/blog/accounts-payable/ap-automation-roi` ("How to Calculate Accounts Payable Automation ROI") as a dedicated post, and the $8–$30/invoice, up to 70%-reduction stat (Gartner/Ardent Partners, per the Zone & Co article) is the kind of number this content type is built around. This is a strong cluster for DocuBite specifically because it can cite its own concrete numbers once available (time-to-review, no-touch rate) the way Vic.ai's homepage does (per the teardown doc: "5X faster invoice processing, 85% no-touch rate by month 6").
9. **AI/agentic framing terms** (emerging, lower competition, rising interest): "agentic AI accounts payable," "AI invoice processing," "autonomous AP." Ramp itself has recently published on this exact framing (`/blog/agentic-ai/agentic-ai-for-accounts-payable`, `/blog/accounts-payable/ai-invoice-processing`), and Vic.ai's entire homepage positioning (per the teardown doc) is built on "AP automation, reimagined" / "autonomous accounting" language. Because this is a newer framing than "AP automation software" generically, competition is lower right now even though the underlying incumbents are large — a reasonable early-mover top-of-funnel bet.
10. **Niche/defensible educational terms unique to DocuBite's actual functionality**: "invoice fraud prevention checklist," "bank detail change fraud," "vendor onboarding red flags," "multi-currency invoice accounting" (DocuBite's ECB-rate-on-invoice-date feature in `multi-currency.tsx` is a genuinely specific, defensible claim most competitor content doesn't address at this level of detail). Volume is likely low per-term but competition is close to zero, and the content directly demonstrates real, shipped functionality rather than generic advice — good for building topical authority around DocuBite's actual differentiation rather than competing head-on for generic category terms.

### Proposed first blog/resources post topics (in priority order)

Ordered to front-load the lowest-competition, most-defensible content while the category terms are being fought for on solutions pages:

1. "How AP fraud actually happens: bank-detail changes, split invoices, and suspicious resubmissions" (ties directly to cluster #3/#10, a real differentiator, no page currently owns this depth)
2. "3-way matching, explained: what a controller checks before a bill gets paid" (#3 — high existing competitor investment, but DocuBite has real matching functionality to show, not just explain)
3. "How to automate invoice processing without replacing your ledger" (#7 — direct match to Ramp's own top-ranking post title pattern, reframed around DocuBite's "keep QuickBooks/Xero or start whole" positioning)
4. "What does AP automation actually cost to *not* have?" / an ROI-framed post (#8) — hold until pricing page (gap 9 in the technical SEO audit) has real numbers, so the post can link to a real pricing page rather than the current placeholder
5. "Multi-currency invoices: why 'today's rate' is the wrong rate" (#10 — unique, demonstrates the ECB historical-rate feature, essentially zero competing content)
6. "Running AP for multiple clients: what a bookkeeping practice actually needs from an inbox" (#2/#7 crossover — ties to the `bookkeepers-running-client-ap` solution page, addresses the "per-client workspace" positioning with an educational framing instead of a product pitch)
7. "Dext alternative for [X]" — hold until the alternative-page naming decision (Open questions) is resolved; do not write this before that decision, since it's the one topic that requires naming a named competitor publicly.

## Open questions / risks

- **Naming competitors publicly is a real policy decision, not just a content one.** The repo's `no-vendor-names-in-the-ui` convention is specifically about not naming the *AI model provider* inside the product UI — it's plausible but not confirmed that the same instinct extends to marketing/SEO content naming category competitors (Dext, Bill.com, etc.) by name. Comparison/alternative pages (cluster #4) are a proven, high-converting content type in this exact category (Ramp, Rippling, Peakflo all run them against Bill.com/Tipalti), but they require naming a competitor on a public page, which is a different decision than what any existing convention covers. Needs an explicit go/no-go before cluster #4 or blog topic 7 above is built.
- **Whether a Resources/blog section is actually in scope for this map.** Map #126 is titled "Multi-page marketing site redesign + SEO," and the IA reference doc (#127's output) found every competitor has a Resources bucket, but no ticket in this map has yet explicitly scoped building the underlying blog infrastructure (routing, CMS/MDX authoring, listing page). This document assumes it should exist because the keyword research strongly supports it (clusters #7–#10 have no other home), but the actual "build a blog" decision belongs to whichever ticket owns IA/#131, not to this keyword-strategy document.
- **Real keyword-volume data was not available in this environment.** No Ahrefs/Semrush/Google Keyword Planner access — every volume/competition judgment above is inferred from how much competitor content and how many independent vendors already target a term, which is a reasonable directional proxy but not a substitute for actual numbers. Before committing content-production budget, a follow-up pass with real tool access should confirm at least the top 10-15 terms' actual monthly volume and keyword difficulty.
- **Geography/localization is unresolved.** `finance-ops-teams` names South African banks and a ZA EFT export specifically, suggesting DocuBite has real usage or intent in a ZA market, but every keyword cluster above was researched in a US-default context (WebSearch has no explicit geo-targeting applied here). If South Africa (or another non-US market) is a real go-to-market priority, a parallel pass on ZA-specific AP-automation search terms and competitors (which are very likely different from the Ramp/Vic.ai/Tipalti set, all US-centric) is a distinct piece of research this document does not cover.
- **Pricing page is a blocker for two clusters, not one.** The technical SEO audit already flagged the placeholder pricing page as blocking `SoftwareApplication.offers` JSON-LD (its gap 9). This document adds that it also blocks the ROI/business-case blog cluster (#8) from linking anywhere credible — both should be sequenced together once real pricing exists, not treated as two separate blockers to solve independently.
- **Which "type"/"quality" solution pages get metadata attention first is a judgment call, not a measured one.** This document recommends prioritizing the `"ap"`-group pages (segment terms) over the `"type"`/`"quality"` pages because `lib/solutions.ts`'s own code comment frames the latter as reassurance rather than the lead pitch — but that's a positioning read, not a traffic-volume-backed prioritization, and should be revisited once real search-console data exists for the live site.
