## What happened
Previous session built the shared `guardLeave`/`ConfirmDialog` wiring in
`components/queue/queue-screen.tsx`. This session found the P0: `ConfirmDialog`
(`components/ui/confirm-dialog.tsx`) attached its own Escape listener via
`window.addEventListener` synchronously in its mount effect — the same
still-bubbling Escape keydown that opened the dialog (document fires before
window in the propagation path) reached that new listener and cancelled the
dialog immediately. Fixed by deferring the listener attach one macrotask
(`window.setTimeout`). Fixes every `ConfirmDialog` caller, not just this guard.
