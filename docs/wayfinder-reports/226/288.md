## Decisions recorded

A flow's name and each existing stage's name/requireOwner/approverIds/minAmount are editable in place, with no schema change — the engine already reads these fields live at decision time, so this exposes existing behavior rather than adding new semantics. Stage order and count stay fixed once the flow can have tasks against it; duplicate + delete remains the only way to change those. No new notification or audit-trail work required.
