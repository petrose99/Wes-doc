## What I did
1. Claimed #327, read the hand-off file left by the prior session (build was
   done — `guardLeave`/`ConfirmDialog` wired into `queue-screen.tsx` — but
   Escape reproducibly did nothing while dirty, root cause unknown).
2. Restarted the dev server + devdb (both were down after the prior session
   ended) and re-ran the prior session's `verify-guard.mjs` — confirmed the
   bug still reproduced live: ✕ opens the confirm dialog, Escape does not.
3. Added temporary `console.log`s to `guardLeave`, `ConfirmDialog`'s render,
   and its `onCancel`/`onConfirm` handlers, then re-ran the Playwright script
   against the live dev server. The trace showed: `guardLeave` correctly sees
   `hasUnsaved()===true` and calls `setPendingLeave`, `ConfirmDialog` renders
   `open: true` — and then, one render later, `onCancel` fires and it closes
   again, all before Playwright's own 400ms wait elapsed.
4. Root cause: `ConfirmDialog`'s Escape listener is attached with
   `window.addEventListener` synchronously inside its mount effect. `window`
   sits after `document` in the DOM's event propagation path, so the same
   still-bubbling Escape keydown that triggered `queue-screen.tsx`'s
   document-level handler (which opened the dialog) went on to reach the
   dialog's brand-new listener and cancelled it — Escape appeared to be a
   no-op.
5. Fixed in `components/ui/confirm-dialog.tsx`: deferred the listener attach
   by one macrotask (`window.setTimeout`), so it only catches the *next*
   keydown, not the one still in flight. This is the shared component every
   confirm dialog in the app uses, so the fix is not specific to this guard.
   Removed all debug instrumentation. `tsc --noEmit` clean on both touched
   files. Committed as 456b5ea.
6. Re-ran `verify-guard.mjs` at 1440: Escape now opens the dialog, Cancel
   returns focus, and Discard proceeds and returns focus to the row — same
   as the existing ✕ path.
7. Attempted the same at 390 and discovered the Users pane specifically
   blocks all editing below desktop width ("Admin is a desktop area — open
   it on a wider screen to make changes", screenshot
   `docs/wayfinder-reports/226/logs/scratch-327/390-companies.png`), so the
