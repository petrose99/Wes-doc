## Decisions recorded
Nango's Connect UI is a headless-friendly wizard, not something DocuBite needs to embed to learn from: backend mints a session via `POST /connect/sessions` (`{token, connect_link, expires_at}`, ~30 min), browser drives it with `nango.auth('<INTEGRATION-ID>')` from `@nangohq/frontend`, resolving to `{providerConfigKey, connectionId}`. States to cover: choosing → authorizing → waiting-on-popup → success, or popup-blocked / popup-closed-by-user / provider-error. There is no Nango-rendered multi-tenant picker — Xero's org picker is the provider's own consent screen; Nango just reads back `tenant_id` into `connection_config`. The backend's authoritative signal is the `AUTH` webhook (`operation: creation|refresh|override`, `success`, `error{type,description}`), reused for both connection-created and token-refresh-failed events — refresh failure should pause posts and flag "needs reconnecting", matching the map's Notes. Delete is `DELETE /connection/{id}?provider_config_key=<key>`; whether it revokes the token at the provider (vs. only purging Nango's vault) is **not confirmed by Nango's docs** and is flagged as an item to verify before DocuBite's disconnect copy claims full revocation. Proxy calls need `providerConfigKey` + `connectionId` (+ Xero's `tenant_id`).
