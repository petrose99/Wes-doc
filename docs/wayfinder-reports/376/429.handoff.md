## Artifacts

- Spec: docs/wayfinder-reports/376/429.spec.md
- Step 4 (this session, committed after this hand-off):
  - `lib/finance/line-account-resolution.ts`: `LineAccountRow` gains optional
    `account_archived_fallback?: boolean` (set only by the orchestration, never the pure functions).
  - `models/documents.ts`:
    - `resolveDocumentCodingItems` now queries `AccountingEntity` (entityType "account", active)
      for the supplier-rule and Default candidate ids in one `findMany`. An archived rule account
      falls back to Default and flags `account_archived_fallback: true`. An archived Default
      resolves to no account at all (`account_external_id: null`), reusing the existing "every
      line has an Account" eligibility check from step 3b instead of new surface plumbing.
    - New `learnSupplierAccountRuleFromApproval(workspaceId, documentId)`: reads the approved
      document's vendor + `codingData.items`, upserts `SupplierAccountRule` on
      `[connectionId, normalizeSupplierName(vendor)]` with the account of the line with the
      largest `reviewedData.line_items[i].amount` (all lines currently share one account per
      resolveLineAccount's scope, but this reads amounts rather than assuming that). Skips
      legacy-chain rows (`account_source: null`) and documents with no vendor. Fire-and-forget
      (console.error on failure), matching models/suppliers.ts's approval-signal writers.
    - New `touchSupplierAccountRuleUsage(workspaceId, connectionId, vendorName, accountExternalId)`:
      bumps `lastUsedAt` on the matching rule; only bumps when the pushed account still matches
      the rule's current account.
  - `app/(app)/workspaces/[workspaceId]/review-actions.ts`: `learnSupplierAccountRuleFromApproval`
    called at all 3 existing "approved" call sites (`updateReviewTaskStatusAction`,
    `bulkUpdateReviewTaskStatusAction`, `decideReviewTaskStageAction`) — the same precedent
    `maybeConfirmAiCoding`/`creditSupplierForCleanApproval` already use for approval-triggered
    side effects. This — not `lib/finance/actions.ts` (an AI-assistant proposal-description
    module with no execution path) — is the real "document transitions to approved" site; the
    schema doc comment's "lib/finance/actions.ts approval path" pointer is stale/aspirational.
  - `app/(app)/workspaces/[workspaceId]/integration-push-actions.ts`: on a succeeded push,
    `pushDocumentToConnection` now calls `touchSupplierAccountRuleUsage` with the vendor and the
    account actually used (`codingItems[0].account_external_id`).
  - Tests: `models/documents.test.ts` gained an `accountingEntity.findMany` mock (default: every
    queried id comes back active, so the pre-existing resolveDocumentCodingItems tests are
    unaffected) plus 2 archived-fallback tests, 3 `learnSupplierAccountRuleFromApproval` tests, 2
    `touchSupplierAccountRuleUsage` tests.
  - `npx tsc --noEmit` clean; full `npx vitest run` green (290 files, 2823 tests).
