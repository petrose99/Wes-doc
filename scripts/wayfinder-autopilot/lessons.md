# Autopilot lessons (generic — travel with the tool to every project)

Product-agnostic only; codebase specifics go to the project's `.claude/wayfinder-autopilot/lessons.md`. Read in full before the pre-build pass on every execution ticket. Append at
close: one line per correction the fix loop had to make that the pre-build
should have caught. Format: `- (#ticket, heuristic) what was missed → what to
do at spec time · check: <grep / script / detector rule that fails when it is
missed>`. **A line without a `check:` is an observation, not a lesson** — it
stays in the ticket report until someone can say how a session would fail it.
The pre-flight runs every `check:` that applies to the surface before the
first capture. Keep it under ~80 lines: when two lines say the same thing,
merge them and generalise; a lesson that has fired three times graduates to
code (a shared primitive, an eslint rule, a detector ignore with a reason) and
leaves this file. This file is the loop's memory; a lesson that is not written
here will be relearned at full cost.

## Build

- (docubite #250) Three detector batches were needed because the first screenshots were only taken after the whole surface was built, and static `impeccable detect` was skipped while it found everything. → Screenshot each new component at 1440/390 as it lands (hook catches static findings); the in-page overlay is the source of truth, run per state (list, pane-open, dialog-open, sheet-open).
- (docubite #252) Detector, critique and evaluate each opened their own browser on the same build; a headless Chromium is 200–400 MB and each pass is minutes. → One capture pass per round (states × widths PNGs + detector JSON + keyboard probe) that all three skills read; re-capture only after code changes.
- (docubite #257, B5 focus) Three focus faults found only by the live probe: a dialog effect keyed on `onClose` re-ran per keystroke and dropped typed text; a context *object* in effect deps looped on every open; a result strip that *replaces* its trigger left focus on body. → Effects key on stable setters/refs, never on callbacks or context objects; when a control disappears on success, the replacement takes focus (`tabIndex=-1` + focus on mount). · check: keyboard probe after each decision prints `document.activeElement`; `body` fails; `eslint react-hooks` on touched files per batch, not once at close.

- (docubite #258, H9 focus, P1) B5 said "focus stays on Save review" and was ticked from the code path; the save bumped a reload key that unmounted the whole content through a loading skeleton, so the focused button was destroyed and focus fell to a wrapper div. → For every action whose success path re-fetches or remounts its container, B5 names the element focus returns to *and how it survives the remount* (stable id + a pending-focus ref consumed on `ready`); a test or probe asserts `activeElement.id` after the action. · check: `grep -n "reloadKey\|key={.*reload\|setState.*loading" <pane>` on a mutation path with no matching `focus(` after `ready`/`loaded` fails; keyboard probe after the action prints `activeElement.tagName` — `DIV`/`BODY` fails.
- (docubite #258, capture, false P0) Playwright's default mouse position is (0,0); a hover-expanding rail/nav there occludes content in every screenshot and reads as a `text-occlusion` P0. → The shared runner parks the mouse away from chrome before each snap (done in `capture-round.mjs`); confirm a detector P0 by opening the one PNG and asking "is anything hovered?" before writing it into the triage. · check: a round script that snaps without `mouse.move` and an app whose nav has `:hover` expansion.
- (docubite #258, capture, false findings) A fixed wait after a mutating click captured the loading skeleton (37 findings on one state). → Wait for the outcome (toast text, row flip, `[role=status]` change), never a fixed ms, before snapping a post-mutation state. · check: `grep -n "waitForTimeout" pw/round.mjs` after a click on a mutating control with no `waitFor(` on an outcome.
- (docubite #271, capture, false negative) A keyboard probe read a transient `[role="status"]` pending string (e.g. "Saving…") only after a `settle()` long enough for the async save to finish and the text to clear, so the probe recorded an empty status and looked like a missing wire-up rather than a timing bug. → Read a transient status/pending string in the same tick as the triggering keypress/click, before any settle; only the *post*-outcome read should wait. · check: a keyboard-probe entry for a pending state whose captured string is empty when the component renders one unconditionally in that state.

- (docubite #271, checks) A build session added a field to an existing mutation call but never re-ran that model's own test file, leaving four stale `toHaveBeenCalledWith` literals that only surfaced at the close-phase full suite. → After editing the data of an existing `update`/`create` call, immediately run that file's own test alongside any consumer test that calls the same function — don't defer verification of a touched call site to the close-phase full run. · check: `git diff --name-only` on the build session includes a model file with no matching `vitest run <model>.test.ts` in the same session's log.

- (docubite #360, H9 recovery, unchecked) Pre-flight's Part B/edge table named all four dialog states (default/busy/error/success) as the contract; the build session's round script (G1) only captured default and dialog-open, never triggering the error path — the measure round scored H9 at 2/4 for a gap in the *capture*, not the code (the error/busy handling was already correct). → A round script's state list is checked against Part B/edge table's own state column before the first measure round, not assembled from memory of "what a user would click"; an offline/error state needs its own capture (`s.offline(true)` around the mutating click) whenever the edge table names one. · check: every row in Part B/edge naming a "busy"/"error" state has a matching state name in the round script.

## Process (the loop itself, not the surface)

- (docubite #257, close phase) Four close sessions went into writing a per-ticket Playwright capture harness; round 1 aborted at state 11 on one bad selector. → The round is a state list on `capture-round.mjs`; the runner isolates every state. · check: `grep -L capture-round docs/wayfinder-reports/*/logs/scratch-*/pw/round.mjs` lists a round script that must be rewritten.
- (docubite #257, hand-off) The hand-off grew to 500+ lines / 13K tokens and was re-read whole at the top of twelve sessions; first-turn context was 47K before any work. → Pointers only, under ~80 lines; history lives in the scratch folder. · check: `wc -l docs/wayfinder-reports/*/*.handoff.md` shows a file over 120 (the context-guard hook nags at that line).
- (docubite #257, close phase) Two sessions captured and fixed without re-running the readers, so the score never moved on paper and no session knew whether the bar was met. → Readers run once per round, first thing after the captures, and their numbers go into the hand-off before the first fix. · check: a close-phase hand-off without a `critique`/`health` line after a round exists.
- (docubite #257, sessions) A Sonnet first session on a phase that had already consumed three sessions spent 29 calls standing up servers and made no progress. → A phase past two sessions runs on the hard model (driver `HARD_AFTER`) and environment bring-up is one command. · check: run-log shows a "no progress" row on a phase with ≥ 2 earlier rows.
- (docubite #259, H5 prevention, P1) The close-phase capture round confirmed a destructive action's confirm dialog by inspecting the code path, not by actually watching the dialog render; the real bug (dialog state lived inside the popover's own content, so Radix unmounted it before it could show) was found only when a targeted retry script checked `dialog title count` after the click. → A confirm-dialog contract (B1/B5) is verified by a live click-through that asserts the dialog's own text is present after the click, never by reading the component tree and assuming Radix's unmount timing is safe. · check: any P1-shaped "unverified" note carried from a prior round's hand-off gets a dedicated single-state retry script before the confirm round, not folded silently into the big capture list where a menu-population race (see next line) can mask it as a capture flake.
- (docubite #259, capture reliability) A 600ms wait after opening the pane was enough for the pane to render but not for its async-registered document context to populate, so the ⋯ menu opened with zero document actions (no Archive/Flag/Delete) and the round's own log read this as "5 findings, all residue" rather than "the menu is empty." → After opening any pane/detail surface, wait for a named menu item's role/text to appear (poll, don't fixed-sleep) before asserting on ⋯ menu contents; a fixed sub-second wait after a client-registered-context pattern is a false negative waiting to happen. · check: a round script that opens a document menu and asserts on item count without first polling for `[role="menuitem"]` to be non-empty.

- (docubite #261, H9 / hydration, P1-class) A card row is one `<a>`; a desktop cell reused inside it carried its own link, so every phone card nested an anchor and React regenerated the tree on the client (1.5 s before any click did anything). The "renders `<a href`" grep listed files, not ancestry. → Part B4 (primitive reuse) gets a row per cell rendered inside an interactive container, naming what it renders. · check: the capture round records `pageerror` + `console.error` per state and fails on any hydration message; the reachability grep asserts no `<a`/`<button` inside the card/row primitive's subtree.
- (docubite #261, keyboard verification) The measure round Tab-walked one width and screenshot the focus hand-off instead of clicking it; the include reader had to fail it. → A keyboard contract in the spec is a probe in the round script before the first measurement: click the control, read `document.activeElement` twice (at once and after the navigation settles) and the URL. · check: `keyboard.json` has one `<state>-<action>-focus-<width>` entry per contract per width.
- (docubite #261, seed vs. probe) A filtered-empty probe silently found no button on two queues because the seed had a row for every facet value, and a query that looked right (`status=rejected`) used the wrong param name. → Before the round, a one-shot probe lists rows/empty-text/button per candidate query; the round script takes only queries that returned zero rows. · check: the probe's output sits in the scratch folder beside the round script.
- (docubite #262, cold-server capture) A freshly-started `next dev` compiles each route on its first hit (50s+); a round that walks many never-hit routes reads most of them as broken on pass one purely from compile stall, not a code defect. → Warm every route a round visits with a `curl` before the first capture, or run the round twice and trust only the second pass. · check: a round script with no pre-warm step against a server started in the same session.
- (docubite #270, gate wait-bump risk) A gate round bumped one state's capture wait (1200ms→2500ms) to fix a dev-overlay-spinner tooling call, then failed with two new findings on unrelated states — the longer wait exposed a pre-existing async-fetch race, not a regression. → A wait-bump is itself a gate-round change: diff its result against baseline before trusting it; revert to the original wait if the bump surfaces findings the diff can't explain. · check: a gate round whose only script change is a capture-wait number gets a before/after diff against the previous baseline, not just a pass/fail read.
- (docubite #286, spec critic) A B1 row marked "reuse existing action" for Resend without opening the callee — it re-created the invitation with the primary role only and dropped the multi-company grants the surface exists to carry; the same pass listed role/remove/bank actions with no server-side owner check because the model functions were assumed to authorise, and serialised masked bank data into every row the client would merely hide. → Before Part B is called filled: open every reused callee and confirm it carries the new surface's data shape; write the authorisation line per mutating action (who, checked where, error code); for any field masked in the UI, state where the masked value is computed and to whom it is serialised. · check: each B1 row cites the callee's file:line; `grep -c <auth-code> <actions file>` ≥ number of mutating actions; a sensitive field has a payload grep that must return 0 for the non-privileged role.
- (docubite #286, uncaptured ≠ finding) A dev server stuck at its first compile (stale Turbopack persistent cache, `.next/dev/cache`, idle CPU — not memory) made the primary state time out; all three readers scored the empty capture as a blank-page P0 and a "Tab never leaves body" P0, and the close session spent a round chasing them. → A capture whose detector JSON carries `error` or a navigation timeout is *uncaptured*, never a finding: list it as "re-run" on the hand-off, warm the route with `curl`, and if the server is idle-but-silent clear its persistent build cache before blaming code. · check: no P0/P1 on the hand-off cites a state whose `detector.json` entry has `error` set.
- (docubite #286, seed contamination) A row-count finding ("personal workspace shows 3 rows, spec says just you") was scored P0 from the screenshot; the rows were planted in the seed by a sibling ticket's dev script, not by app code. → Before scoring a data-shape finding against the spec, query the seed and grep the visible names across dev scripts. · check: the finding cites the query proving the rows come from an app code path.
- (docubite #329, critique scale) A critique reader scored every "no violation found" heuristic as 0 instead of 4, using `evaluate`'s issue-count convention (0=no issues) instead of critique's own quality scale (4=excellent) — 9/40 became 33/40 on a re-score of the same evidence. → Before triaging a critique score that reads as a wall of "no violation found" text against low numbers, re-check which convention the reader used against the skill file's own Scoring Guide. · check: any heuristic ≤1 whose own prose says "no violation found" gets this check before it's trusted as real.
- (docubite #329, sandboxed close session) The Bash tool refused every attempt to start a background/long-running process (`npm run dev`, bare `next dev`, even `python3 -m http.server`) with "requires approval" and no human present — unlike the interactive `nohup`/`setsid` recipe assumed by the project's live-UI memory. → Try starting the dev server once as a standalone check before planning a capture round; if refused, it's a hard block this session (not a syntax issue to retry with wrappers) — re-score existing captures with a fresh reader agent instead when the code change is text/class-only.
- (docubite #287, close phase, misdiagnosed fix) A popover trigger fully hidden (`hidden group-hover/rail:block ...`) in its collapsed state broke Radix's `onCloseAutoFocus` on Escape: the library tries to restore focus to the trigger at the instant it flips its own `aria-expanded` back to `false`, so a CSS rule gated on `aria-expanded=true` (or on hover/focus-within, both already gone by then) makes the trigger `display:none` right when focus needs to land there — falls back to `body`. Two gate rounds (c1→c3) chased the wrong root cause (a *different* line's contrast) before a confirm-round reader caught, by reading the keyboard probe JSON directly rather than trusting the fix-batch note, that the actual focus-loss bug was untouched. → A collapsed/compact popover or menu trigger must always render as a real, focusable element; only its *label/decoration* may be conditionally hidden by CSS. Never gate the trigger element itself behind a hover/focus-within/aria-state CSS class when a library's own focus-restore reads that same state to decide where to land. · check: `grep -n "hidden group-hover.*block" <trigger-wrapping-element>` — if the match is the `<button>`/`<a>` itself (not a child span/text node), it's a candidate for this bug; the round script's `keyboard.json` `*-escape-closes` probe resolving to `"body"` at any width confirms it live.

- (docubite #362, H5, gate round c1→c2) A "gate this field on a locked/read-only state" fix folded
